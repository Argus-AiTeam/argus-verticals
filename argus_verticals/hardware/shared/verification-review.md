## Host checks and independent review

The host supplies the selected provider's current completion check as raw
evidence after the Engineer turn. Reviewer uses read/search tools to inspect
original requirements, source, oracle, raw observations and that host result;
Reviewer does not need shell permission and must not claim personal execution.
Missing or failed host evidence is incomplete. An Engineer-authored file
labeling a run as Reviewer execution is not a substitute. Do not create a
separate validation-only task or repeat Engineer runs to impersonate Reviewer.

The host checks the execution project under the saved workflow scope, not
the session-state directory or an unscoped full workflow. Ordinary record checks
do not replay commands from project records. Explicitly selected bounded native
adapters retain their own replay rules. A record check does not run an arbitrary
project evaluator, acquire a claim, issue an owner or resume a stopped daemon.
The final stage still enforces its deterministic completion check.

## Accelerator precision and claim boundaries

For accelerator work, preserve the project's original numerical contract and
independent evaluator rather than replacing them with generic PASS criteria.
Record weight/activation, accumulator, residual and K/V formats separately;
an FP16 operator boundary does not imply all internal state is FP16. Keep
packing order, signedness, group size, scales/zero points, reduction order,
rounding points/modes, overflow, saturation, subnormal and invalid-value rules.
Rounding once after the full reduction is not equivalent to summing rounded
group outputs. Do not substitute a CPU floating-point reduction for an exact
integer or RTL computation merely because final text looks plausible.

Use directed cancellation, halfway/tie, group-boundary and extreme-value cases
with the project's specified bit/ULP/tolerance and independent reference. Bind
the original contract, oracle dependencies and retained input fixtures to the
run using the provider's input mechanism. Preserve native project checks of
large model packages; do not duplicate all weights just to fill a generic form.
Never use expected outputs to select candidate bits, clamps or rounding modes.

Distinguish implementation tests, CPU numerical experiments, RTL simulation,
physical implementation and measured hardware. A repaired wrapper is not a
successful numerical hypothesis; a rejection remains a rejection. A task
that failed before a claim or numerical invocation is unmeasured, not a
numerically rejected experiment. Passing record checks cannot promote any
of these boundaries or relax the selected stage's original acceptance.

## Continuation without consuming old work

Inspect the current native task, runtime identity, retained inputs and review
before applying a saved continuation note. A repository snapshot is not live state.
Do not replace an old runtime with the ambient checkout, clear historical
claims, revive failed owners or reuse consumed output namespaces.

Before an authorized new scientific run, validate the real entry contract,
dependency list and fresh-process import order with explicitly no-claim,
non-scientific fixtures. Use the existing Manager lifecycle to issue an owner;
Engineer cannot repair an authority mismatch by editing task state. Preserve
timeouts, interruptions and failed attempts. Missing in-memory K/V state is
not restored by a source checkout or an unrelated disk checkpoint.
